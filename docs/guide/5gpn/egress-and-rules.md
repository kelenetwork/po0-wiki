# 出口与分流管理

日常管理全部在 Telegram Bot 或内网 Web 面板完成，两者功能一致、即时热更新，无需重启服务。

## 概念先行

- **KFC 本机出口**：国外流量直接使用 KFC 机器的公网 IP 出去（内部兼容名 `DIRECT`）
- **代理出口**：粘贴节点分享链接添加的落地节点（ss / vless / vmess / trojan / hysteria2 / tuic 等）
- **国外默认出口（FINAL）**：未命中任何规则的国外流量走哪里。切换它**不影响**国内直连，也**不影响**自定义分流规则

国内域名与国内 IP 始终由内置规则（11 万条域名库 + GEOIP）处理，不受出口切换影响。

## 添加出口

Bot → 🌐 国外默认出口 → ➕ 添加出口，粘贴节点分享链接即可。

- 出口名称自动取节点备注名（内部规则名为其小写字母数字形式）
- 添加时会做**端到端联通验证**：经该出口真实访问外网并校验响应，不通不入列表
- mihomo 协议栈缺失时自动下载安装

## 切换国外默认出口

Bot → 🌐 国外默认出口 → 「国外走 xxx」。

- 切换前强制端到端验证，坏出口拒绝切换、当前出口不变
- 每个出口带「🧪 测」按钮，随时检测连通性与耗时
- 删除当前出口会自动回落 KFC 本机出口

> 💡 某些国外服务（如 WhatsApp 的 Meta 裸 IP 段）从 KFC 本机公网直连可能不可达。遇到「官网能开、App 连不上」时，优先把国外默认出口切到代理出口，或为对应网段加分流规则。

## 自定义分流规则

Bot → 🧭 分流规则 → ➕ 添加。格式：`类型,值,动作`

```text
DOMAIN-SUFFIX,openai.com,proxy:节点名   # 指定域名走指定出口
DOMAIN-SUFFIX,example.cn,direct         # 指定域名走 KFC 本机
DOMAIN-KEYWORD,ads,block                # 关键词拦截
IP-CIDR,31.13.0.0/16,proxy:节点名       # 指定网段走指定出口
```

- 类型：`DOMAIN` `DOMAIN-SUFFIX` `DOMAIN-KEYWORD` `IP-CIDR` `RULE-SET` `GEOIP`
- 动作：`direct`（KFC 本机公网）· `block` · `proxy:<出口名>`
- 新规则插入最前，优先级最高；添加页会动态列出你现有的出口名
- 域名会先解析目标 IP 再参与 `IP-CIDR` / `GEOIP` 匹配

## 修改定位

Bot → 📍 修改定位：一键修改手机上报的地理定位，适合打卡、区域限定 App 测试等场景；随时可一键恢复真实位置。定位修改在网关侧完成，不改动手机系统。

## 内网 Web 面板

手机连着内网卡时，浏览器直接打开安装时输出的面板地址即可，**免登录直达**——面板只接受内网卡来源访问，公网完全无法连接。
