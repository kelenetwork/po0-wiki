# 连通诊断与常见问题

## 逐层诊断

遇到「某个网站打不开」，先用诊断定位坏在哪一层，不要盲猜。

**Telegram Bot**：🩺 连通诊断 → 输入域名（支持直接粘贴完整 URL）。

**命令行**：

```bash
5gpnd probe youtube.com
```

输出五层结果，任何一层失败都会指明原因：

```text
[1] 入口   probe 本地发起                          ✅     0.0ms
[2] 策略   RULE-SET,cn-domain [域名] → 直连         ✅     0.1ms
[3] 出口   KFC 本机出口（IPv6 能力=false）           ✅     0.0ms
[4] 连接   TCP 36.51.224.126:443 已建立             ✅    59.6ms
[5] 应用   TLS 1.2 证书校验通过                      ✅   109.9ms
结论：正常（总计 169.7ms）
```

## 常见问题

### 可以用其他厂商的 VPS 吗？

暂时不行。5GPN 内网卡的流量只会送达 KFCHOST 的网段，网关必须部署在 KFC 机器上。

### 移动 / 电信 / 其他省份的联通卡可以吗？

目前仅支持**浙江联通卡**，且需自行办理后在 KFCHOST 控制台绑定。其他运营商与省份暂不可用。

### 装了描述文件后 Wi-Fi 也受影响？

这是 **Relay 模式**的固有行为：Apple Network Relay 是系统级配置，蜂窝与 Wi-Fi 同时生效。希望 Wi-Fi 完全不受影响，请删除 Relay 描述文件，改装「**蜂窝 DNS 模式**」描述文件（Bot → 客户端接入）。

### WhatsApp 官网能开，但聊天连不上？

WhatsApp 聊天使用**硬编码的 Meta 裸 IP**，部分网段从 KFC 本机公网直连不可达。两种解法：

1. 把国外默认出口切到代理出口（Bot → 国外默认出口 → 国外走 xxx）
2. 保持 KFC 本机出口，为 Meta 网段加分流规则：

```text
IP-CIDR,31.13.0.0/16,proxy:节点名
IP-CIDR,66.220.144.0/20,proxy:节点名
IP-CIDR,69.63.176.0/20,proxy:节点名
IP-CIDR,157.240.0.0/16,proxy:节点名
```

### 切换出口后国内也走出口了？

不会。出口切换只影响「未命中规则的国外流量」；国内域名/IP 始终由内置规则（11 万条域名库 + GEOIP）本地直连或 KFC 直连，自定义分流规则也不受影响。

### 某个国内 App 变慢？

可能该域名未被识别为国内。先 `5gpnd probe <域名>` 确认判定结果，然后在 Bot / 面板加一条 `direct` 规则。

### 国外网站全部打不开？

运行 `5gpnd probe youtube.com`。若提示未配置代理出口，说明国外流量实际从 KFC 本机直出，部分目标不可达 —— 添加落地节点并切换出口即可。

### 描述文件链接 / 面板打不开？

两者都**仅内网卡来源可访问**。请关闭 Wi-Fi，确认手机正在使用 5GPN 卡的蜂窝数据。

### 服务器升级后需要重装描述文件吗？

一般不需要：分流逻辑在服务端，升级即生效。只有升级日志明确注明「直连名单更新」时，才需要在 Bot 重新获取并安装（Token 与网关身份保持不变，先删旧文件再装新文件）。

### 网关挂了手机会断网吗？

不会整机断网：Relay 描述文件启用了 `AllowDNSFailover`，网关故障时自动回退系统 DNS；蜂窝 DNS 模式下连 Wi-Fi 永远不受影响。

## 反馈问题

反馈时请附上：`5gpnd probe <目标>` 的完整输出、所用接入模式（蜂窝 DNS / Relay / Android）、当前国外默认出口。
